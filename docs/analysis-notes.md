# Static Analysis Guidelines & Heuristics Policy

## Philosophy of Analysis

Xaynx Reverse Lab strictly follows an objective, evidence-based reverse engineering model:

1. **Absence vs. Unavailability**:
   - `Confirmed Absent`: When header structures or directory tables are inspected and confirm that a section/table/symbol set does not exist (e.g. data directory size is 0, or `.symtab` section header is missing).
   - `Unavailable (Not Parsed)`: When section headers are stripped, corrupt, or of a type not yet parsed. We never claim a feature is absent when we simply could not read it.

2. **Heuristic Observations vs. Malicious Verdicts**:
   - No single static indicator proves malicious or benign intent.
   - Legitimate software (anti-cheat engines, game loaders, software protectors, debuggers, system utilities, JIT compilers) regularly utilizes high entropy, RWX sections, or API hooks.
   - Findings in Xaynx Reverse Lab are explicitly labelled as `[heuristic]` observations. The application never labels a file as "malware" or "infected".

## Implemented Heuristic Rules

- **Writable and Executable Sections/Segments**: Detects headers with both write and execute permissions flags (`IMAGE_SCN_MEM_WRITE | IMAGE_SCN_MEM_EXECUTE`, `SHF_WRITE | SHF_EXEC`, or `VM_PROT_WRITE | VM_PROT_EXECUTE`).
- **Section Bounds Out of Range**: Detects headers whose raw offset + raw size exceed the physical byte length of the file on disk.
- **High Shannon Entropy**: Sections with entropy $\ge 7.2\text{ bits/byte}$ over $\ge 4096\text{ bytes}$ are noted as containing potentially compressed, packed, or encrypted data.
- **Entry Point Discrepancies**: Flags when the entry point virtual address falls outside any mapped executable section.
- **Process Manipulation API Imports**: In PE binaries, imports of functions such as `VirtualAllocEx`, `WriteProcessMemory`, `CreateRemoteThread`, `SetWindowsHookEx`, and `NtUnmapViewOfSection` are recorded neutrally for analyst awareness.

## Shannon Entropy Analysis

The Entropy Heatmap independently streams files in configurable blocks (256 bytes
by default) and reports block entropy using
$H=-\sum_{i=0}^{255}p_i\log_2(p_i)$, where $p_i$ is the observed probability of
byte value $i$. The overall value is calculated from the distribution across the
entire file; the average block value is an unweighted mean of block entropies.
The incomplete final block is measured using its actual byte count. Empty files
have no defined entropy statistics, rather than a reported zero.

Entropy is sensitive to block size and is not a reliable stand-alone classifier:
compressed, encrypted, and packed data can be high-entropy, but so can benign
content. A low value likewise does not establish that content is benign. The
visual threshold highlights variation only and never produces a maliciousness
verdict.

## Explainable Static Analysis

The Static Analysis page combines findings from the existing format parser,
Strings Explorer, Entropy Heatmap, and an optional CFG result previously
generated by the user. It does not execute files or classify them as malware.
Rules report structural bounds and permissions, virtual/raw size gaps, entry
point mapping, selected imported API capabilities, deterministic string
categories, high-entropy regions, and selected CFG complexity or unresolved
flow. Correlations connect independent observations but are not proof that
they are related at runtime.

The score is an evidence-prioritization aid only. Severity weights are 0, 8,
18, 32, and 45 for informational through critical; candidate points multiply
the severity weight by confidence and evidence-quality percentages. The
strongest contribution per evidence group is counted, correlations contribute
zero, and the final rounded score is capped at 100. Fewer than two independent
positive-weight evidence groups means the score is inconclusive. This is not a
probability, reputation score, or malware verdict.

CFG indicators appear only when a valid CFG result has already been produced;
the static engine does not analyze every function. Relocation records and
debug identifiers are parsed and surfaced by the Function Explorer/XREF, but
they are not currently inputs to static-analysis rules. Imports may
be unused, strings may be documentation or dead data, and high entropy may
come from benign compression or embedded assets. Every finding should be
reviewed with its evidence and benign explanations.
